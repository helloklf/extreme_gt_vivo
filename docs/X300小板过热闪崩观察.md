# X300 小板过热充电闪崩观察（bat_board_temp ↔ quiet-bot-right-ntc 假设）

记录日期：2026-11-13
状态：观察记录 + 假设，对应关系尚未验证；fccc 侧的接入尝试已撤销（见下文）。

## 现象

X300 高功率充电中后程，监控到 `bat_board_temp`（小板 NTC）冲入过热区间后，
充电功率突然闪崩。形态与 iQOO15 的适配器过热闪崩类似
（见 [iQOO15充电中后程功率闪崩分析.md](iQOO15充电中后程功率闪崩分析.md)，
vfcp 栈在适配器 85°C 时直接丢快充），但热源是机身小板而不是适配器。

## 假设：bat_board_temp 的物理对应物是 quiet-bot-right-ntc

- X300 上存在 `/sys/class/thermal/thermal_zone63`，type 为
  `quiet-bot-right-ntc`，空闲读数 44.9°C（2026-11-13 在本机实测）。
  命名指向主板右下角的 NTC，与"小板"（bat_board_temp）的位置描述吻合；
  两者很可能就是同一颗传感器，分别挂在 cms 节点和 thermal zone 框架下。
- **待验证**：充电过程中同时记录 `bat_board_temp` 与 `thermal_zone63/temp`
  两条曲线，确认是否一一对应（同涨同落、幅度一致）。

## fccc 接入尝试（已撤销，未进入任何发布版本）

曾尝试把 quiet-bot-right-ntc 作为第三温度源接入 fccc（与适配器温度同一
归一化手法：75°C 满量程对齐 L3+shift，三者取最大进温度包络，日志加
`quiet_0.1C` 字段）。动手实测前分析出三个结构性弱点，随即从工作区撤销：

1. **发言点太晚**：缩放值必须超过电池温度才能接管。电池 45°C 时，
   小板要冲到 ~71°C 才获得发言权，接手窗口只有 4°C 宽。
2. **斜坡追不上**：fccc 的斜率棘轮以每拍百分比工作，压流全程要几分钟；
   小板热容小，从 55°C 冲到 75°C 只需几十秒。
3. **归一化语义错配**：满量程映射让干预阈值随电池温度轴漂移。电池是
   大热容慢对象，缩放归一化合理；小板是低热容局部热点，必须用绝对阈值。

## 后续方向（若要做）

- fccc 监控该传感器时改用**绝对阈值**，不随电池温度轴缩放，例如：
  小板 ≥ 55°C 开始按比例压流、≥ 62°C 无视包络直接拍地板。
- 或直接监控 X300 的 `bat_board_temp` 节点本身
  （若 `/sys/class/cms_class/bat_board_temp` 可读，语义比扫 thermal zone 更直白）。
- 先验证传感器对应关系，再决定监控哪个节点。

## 已定案：turbo 一刀切保护（2026-11-13 实现）

放弃渐进式干预，改为复刻 OEM 的热预算逻辑：fccc 监控
`quiet-bot-right-ntc`，**每次连接充电器后满血（15600）；一旦小板 NTC 达到
70.0°C，上限一步砍到 11700mA（75%）并且本次充电不再恢复**，拔插才重置。
70°C 与 75% 对应官方 turbo 时间窗内小板恰好能承受的热量——官方已经很懂
这个界限，我们只是把同样的预算做成显式闩锁。与上文撤销的归一化方案不同，
这里用绝对阈值，正是"低热容局部热点不走电池温度轴"的结论。实现细节：找到
zone 后先往其 `emul_temp` 写 0 清除其它模块可能留下的温度伪装，再开始监控
（该节点需要内核编译进 CONFIG_THERMAL_EMULATION 才存在，写失败只告警不退出）。
