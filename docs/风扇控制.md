# fanctld:独立风扇控制器

> 面向带风扇的 vivo 机型(iQOO 15 Ultra / V2546A),用两条独立曲线分别驱动
> "SoC 温度"和"电池温度",取两者占空比的最大值。

## 两个温度源

| 曲线 | 默认来源 | 说明 |
|---|---|---|
| `pop` | `thermal_zone` 里 `type=ddr` 的那一路 tsens | 只读一个节点。DDR 在封装堆叠 PoP(Package-on-Package)上,与 CPU 结温接近、略低(核 90°C 时 DDR 约 80°C),所以叫 `pop` 而不是 `cpu`;也省掉遍历几十个 `cpu-*` 传感器 |
| `batt` | `/sys/class/cms_class/main_batt_temp` | 与 `tpoff` 同源,单位 0.1°C |

> **和 tpoff 的配合**:`tpoff` 的 both 模式(iQOO15)会伪造 `main_batt_temp`,
> 风扇会被假低温骗到不转。这种机型请在 `fan.conf` 里把
> `batt_src` 改成 `/sys/class/cms_class/bat_btb_temp`(真实、不被覆盖)。

## 配置(fan.conf,放在二进制同目录)

```
pop=85:100 75:80 68:70 60:50 50:30 45:0
batt=48:100 43:80 41:60 39:40 37:20 35:0
batt_src=/sys/class/cms_class/main_batt_temp
```

- PoP 温度源固定按 `type=ddr` 匹配,不开放配置;
- 起转脉冲固定 45%、占空比死区固定 5%、最小占空比固定 22%、降速限幅固定 5%/轮、轮询 1 s,均不开放配置;
- 温度单位 °C,转速 0–100%;按温度从高到低写,两点之间线性插值;
- 高于第一点取第一点,低于最后一点取最后一点(**最后一点给 0 就会自动停转**);
- 两路各算一个占空比,最终取最大值。

## 关键实现细节(来自 2.5.0 的实测经验)

- `/dev/fanpwm` 的 `open()` 会给风扇上电、`release()` 断电 → **句柄全程保持打开**,
  退出时才写 0 并关闭;
- 停转起步先写 45% 的起转脉冲 800 ms,越过静摩擦后再回到目标值;
- 运行最小占空比固定 22%(实测 20% 才起转,留 2% 余量);
- 占空比死区固定 5%:变化小于该值不重写,避免曲线边界处每秒 1% 的抖动;
- 降速限幅固定 5%/轮:每轮最多降 5 个点,避免温度一帧波动就骤降/骤停;
- 配置暂不可用或 `/dev/fanpwm` 尚未出现时,守护进程保持运行并每 5 秒重试;
  写入失败会关闭失效句柄并尝试重开,重开失败后每 5 秒重试。明确收到 SIGTERM/SIGINT 时仍写 0 并退出。

## 用法

```bash
# 常驻(配置取二进制同目录的 fan.conf)
fanctld

# 指定配置
fanctld /data/adb/modules/extreme_gt_vivo/fan.conf

# 看一次当前温度和占空比
fanctld status /data/adb/modules/extreme_gt_vivo/fan.conf
```

## 模拟测试(host)

`test/sim_fanctld.c` 把 syscall 层换成模拟文件系统(内存目录树 + 记录写入),
在主机上跑**同一份 fanctld.c**,覆盖真实分支:

```bash
# Linux / WSL
gcc -DHOSTTEST -O1 -Wall -Wextra -Werror src/fanctld/fanctld.c test/sim_fanctld.c -o sim_fanctld
./sim_fanctld
```

用例与期望输出:

| 用例 | 验证点 | 实际写入序列 |

## 测试情况

- 主机模拟:所有用例通过(见上);
- X300(无风扇):验证了 zone 查找、曲线插值、`status` 输出;
- 用普通文件冒充 `/dev/fanpwm` 验证了完整写入链路:
  `0 -> kick 45 -> 90`,死区生效(6 秒内无重复写入),退出写 0;
- **未在真风扇硬件上跑过**(需要有 iQOO 15 Ultra),上机前建议先用
  `fanctld status` 对照 `ddr` 实际温度和预期转速。
